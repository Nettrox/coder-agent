Retriever Module

Module Version: v0.1

Status: Active

Last Updated: 2026-07-06

⸻

Purpose

The Retriever module is responsible for selecting the smallest useful subset of project information required to complete a user request.

Rather than exposing the entire project to downstream AI agents, the Retriever identifies only the files, symbols, and knowledge entries relevant to the requested task.

The Retriever is the first reasoning layer of the AI pipeline.

⸻

Responsibilities

The Retriever module must:

* Analyze the implementation plan.
* Query the Knowledge Database.
* Select relevant project files.
* Select relevant project symbols.
* Minimize context size.
* Preserve implementation accuracy.
* Produce deterministic retrieval results.

The Retriever must not:

* Generate implementation code.
* Modify project files.
* Build coding context.
* Apply project changes.
* Validate generated code.

⸻

Retrieval Strategy

The Retriever follows these principles:

1. Prefer existing project files.
2. Prefer indexed knowledge over raw source code.
3. Retrieve the minimum useful context.
4. Avoid unrelated files.
5. Preserve deterministic behavior.
6. Never guess unavailable information.

⸻

Constraints

The Retriever:

* must never modify project files
* must never generate implementation code
* must minimize retrieved context
* must remain deterministic
* must rely on structured knowledge whenever possible
