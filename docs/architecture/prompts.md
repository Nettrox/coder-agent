Prompt Architecture

Architecture Version: v0.1

Status: Active

Last Updated: 2026-07-06

⸻

Purpose

This document describes the Prompt Builder architecture used by the AI Coder Agent.

Instead of storing complete prompts inside individual agent files, prompts are assembled dynamically from reusable shared rules, agent definitions, and runtime context.

This approach reduces duplication, improves maintainability, and ensures consistent behavior across all AI agents.

⸻

Overview

Every AI agent receives a runtime prompt generated by the Prompt Builder.

The Prompt Builder combines:

* Shared Runtime Rules
* Agent Definition
* Runtime Context
* User Request

into a single deterministic prompt.

No AI agent owns the complete prompt.

The Prompt Builder is the only component responsible for assembling runtime prompts.

⸻

Core Principles

Single Source of Truth

Shared rules exist only once.

Changing a shared rule immediately affects every AI agent.

⸻

Separation of Concerns

Prompt logic is separated into reusable layers.

Each layer has one responsibility.

⸻

Runtime Assembly

Prompts are assembled immediately before an AI agent executes.

No static prompt files are generated manually.

⸻

Consistency

Every AI agent follows the same prompt construction process.

This guarantees predictable behavior across the pipeline.

⸻

Extensibility

New agents can be added by providing only an agent definition.

Shared rules automatically become available.

⸻

Prompt Components

A runtime prompt is composed of four layers.

Shared Rules
      │
      ▼
Agent Definition
      │
      ▼
Runtime Context
      │
      ▼
User Request
      │
      ▼
Final Runtime Prompt

⸻

Shared Runtime Rules

Shared rules apply to every AI agent.

Examples include:

* JSON rules
* Response rules
* Coding rules
* Project rules
* Quality rules

These documents are stored in:

prompts/shared/

⸻

Agent Definitions

Each AI agent defines only its own responsibilities.

Examples:

* Planner AI
* Retriever AI
* Context Builder AI
* Coder AI
* Validator AI
* Fixer AI

Agent definitions are stored in:

prompts/

⸻

Runtime Context

Runtime context is generated by the pipeline.

Examples:

* planner_output
* retriever_output
* context_builder_output
* file_context
* project reports
* knowledge summaries

Runtime context changes for every execution.

⸻

User Request

The original user request is always included as the final dynamic input.

It represents the objective of the current execution.

⸻

Prompt Assembly Process

The Prompt Builder follows the same process for every AI agent.

Load Shared Rules
      │
      ▼
Load Agent Definition
      │
      ▼
Load Runtime Context
      │
      ▼
Load User Request
      │
      ▼
Assemble Prompt
      │
      ▼
Validate Prompt
      │
      ▼
Cache Prompt
      │
      ▼
Execute AI Agent

⸻

Prompt Validation

Before execution, every assembled prompt is validated.

Validation checks include:

* required sections exist
* runtime input exists
* prompt is not empty
* agent definition is loaded
* shared rules are included

Invalid prompts stop pipeline execution.

⸻

Prompt Cache

Every generated prompt may be cached for debugging and traceability.

Example location:

.ai-agent/cache/prompts/

Cached prompts make it possible to reproduce previous executions.
